# NETRA-Mail — current idea description and abstract (4.8)

## Idea description

NETRA-Mail helps users and analysts move from an email warning to an evidence-backed investigation. A user selects an email in Gmail; after consent, NETRA retrieves its original message and examines language, links, sender authentication and static attachment evidence. It explains why review is recommended and preserves the original evidence for later inspection. Password-protected PDF content can be reviewed through an optional user-consented password flow, with limitations shown when inspection is incomplete.

The investigation view combines observed mail-server geography with sourced network information, DNS records and domain-registration dates. RDAP and optional licensed WHOIS enrichment identify returned registrar and registration information without guessing missing values. Domain age is computed only from a valid registration date. IP geolocation describes infrastructure, not a person's location; ASN owner, ISP and hosting provider are kept distinct. Optional VPN/proxy, timestamped Tor and malware-infrastructure reputation observations retain their sources and freshness and do not establish sender intent.

NETRA keeps weighted shared-indicator matching and adds explicit NetworkX graph traversal over qualified relationships among messages, sender addresses, URLs, attachment hashes and infrastructure. The dashboard exposes the exact supporting evidence for candidate campaign clusters. Common cloud infrastructure or a registrar alone cannot create a qualified campaign edge. Preserved evidence, graph relationships and plain-language explanations can be exported together in forensic reports with integrity and custody records.

## Abstract

NETRA-Mail is an AI-assisted email threat-analysis and forensic investigation platform developed for SIH Problem Statement 26106. It combines NLP and a provisioned machine-learning content model with email authentication, URL analysis, static attachment inspection and evidence preservation. User-initiated Gmail analysis connects the selected original message to a dashboard showing findings, uncertainty and practical review guidance. Infrastructure enrichment incorporates DNS, RDAP registration records, optional licensed WHOIS fallback, public-IP geolocation, BGP network information and optional sourced anonymisation and malware-reputation observations. An explicit evidence graph extends weighted indicator matching with NetworkX bounded neighbourhood traversal and connected components over qualified relationships, retaining the evidence behind candidate campaign clusters. The system avoids equating shared infrastructure with a common attacker, feed absence with safety, or IP location with human identity. Reports combine observations, source metadata, graph evidence and forensic integrity records. The implementation is tested using synthetic integration fixtures and public-source acceptance checks; actual hosted Gmail consent and credential-dependent services require separate live verification.
